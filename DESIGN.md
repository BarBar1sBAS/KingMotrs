# КингМоторс · дизайн-система v2

## Наша команда
Секция #team между #about и #reviews: h2 «Наша команда», подпись о вымышленных именах, должностях и портретах. Семантический список из пяти сотрудников, портреты 4:5, имя h3 и должность под фото. Фон paper, существующие Manrope/Golos и токены; без оболочек карточек, карусели и дополнительной анимации. Пять колонок от 1200px, три на 768–1199px, одна до 767px. Текст растёт свободно. В обеих навигациях ссылка «Команда». Локальные WebP640×800 с lazy loading и описанием демо-портретов.

Единый актуальный визуальный источник: `prototype/tokens.css`, `prototype/style.css`, `prototype/motion.css`; поведение — `prototype/app.js`. Browser exports в `output-v2/mockups`. Старая v1, её output, токены и визуальные инструкции удалены. Содержательные реестры docs/ сохранены.

## Композиция и бренд

Большая фотография обслуживаемого автомобиля и короткий уверенный заголовок. Графитовая шапка/hero, светлый каталог, фотоблок доверия, редакционный блок отзывов, компактные FAQ/бизнес/вакансии, графитовые контакты с контрастной формой. Ритм услуг: две крупные фотографии и четыре меньшие. Никаких пустых декоративных панелей, светящихся рамок, счётчиков достижений или выдуманных звёзд.

Логотип: исходные девять path сохранены, допускается только обрезанный viewBox. Не вращать слово и не деформировать знак. Минимальная ширина в шапке 153 px; desktop186 px. Охранное поле — не меньше высоты буквы вокруг изображения. Цвета исходника не перекрашивать.

## Компоненты и интерфейсы

- Header: logo, links[{label,href}], phone, bookingHref. MenuButton связан с nav через aria-controls/expanded. Escape закрывает, возвращает фокус. Выбор якоря закрывает, переводит фокус к разделу.
- Hero: title, lead, photo, photoAlt, originCaption, bookingHref, phone. Фото справа desktop, отдельный нижний кадр mobile. Одна главная кнопка.
- ServiceGroup: id, title, description, image, jobs[]. Базовый no-JS HTML: details/summary. При JavaScript карточка — button с aria-haspopup=dialog; содержимое открывается в общем native dialog, не меняя размеры/положение карточек. Без JavaScript сохраняется нативное details как резервный доступ к содержанию.
- ServiceJob: stable slug, title, intro, workScope, priceNote, bookingLabel. Нативное вложенное details; hash открывает предков. 33 идентификатора сохраняются в карте контента.
- Review: author, date, exactText, sourceURL. Один крупный отзыв, два рядом, ещё четыре под native details. Не сокращать так, чтобы менялся смысл, не генерировать аватары людей/рейтинги.
- FAQ: question/answer в details. Business/Careers используют тот же принцип с компактным тизером.
- Booking: телефон required (11 цифр, начало7/8), имя optional max80, запрос optional max1500; consent required, без предвыбора. Выбранная услуга контекстом, можно убрать.
- FormState: idle, invalid, sending, success, error; в прототипе дополнительно checked. UI демо-состояний отделён под раскрытием. success всегда подписан демонстрацией. Реальная реализация показывает успех только после ответа API; повтор при ошибке сохраняет поля и блокирует двойную отправку.

Валидация рядом с полем, aria-invalid + aria-describedby, фокус первого неверного поля. Статусы role=status/aria-live=polite. No-JS: настоящая запись по телефону; демонстрационный submit disabled. Клавиатура использует нативные ссылки/кнопки/details. Focus два контрастных кольца; внутри обрезаемой карточки inset.

## Движение и ограничения

Полный контракт в `docs-v2/motion.md`. Интро820ms, один раз за сессию, без блокирующей маски. Reduced-motion120ms или без движения. Не измерять качество дизайна только отсутствием JS-ошибок: независимые визуальные/технические отчёты раздельны. Это Chromium-прототип, не подтверждение готовности Safari/Firefox, screen reader, CRM или производительности рабочего сайта.

## Яндекс Карта перед футером

`#location`: светлая секция после записи и перед футером. Desktop: адресная колонка и широкая карта в пропорции0.8/1.65, gap64px; tablet0.85/1.15 и32px; mobile одна колонка и30px. Карта480px desktop/tablet и360px mobile. Рамка1px line, радиус8px. Внутренние элементы Яндекс Карт не перекрашивать, не закрывать логотип/атрибуцию.

Используется настоящий iframe Яндекс Карт с точкой сервиса и центром43.927428,56.317015. Координаты и route URL сверены с действующей страницей контактов. Iframe lazy, title описывает место, без API-ключа и копирования аналитики старого сайта. Вне iframe всегда доступны адрес, часы, телефон, «Построить маршрут» и ссылка «Открыть в Яндекс Картах» — работают независимо от загрузки виджета. На мобильном iframe не перекрывает контактную карточку. Новый контактный якорь из блока записи ведёт к#location.

## Услуги в модальных окнах — актуальное решение владельца
Вместо расширения карточек: один native dialog в top layer, ширина до820px, максимум viewport−64px desktop /−24px mobile. Внутри шапка с названием направления и доступной кнопкой закрытия44px, ниже прокручиваемый список работ. Подробности33работ остаются native details внутри модалки. Открытие группы никогда не изменяет сетку каталога.

Закрытие: крестик, Escape, pointer down/up по фону. Содержимое возвращается в исходную карточку, фокус — на открывшую кнопку, scroll — в прежнюю позицию. Native showModal блокирует фон и удерживает клавиатурную навигацию внутри. Страница блокируется от прокрутки только пока открыт диалог (не для маскировки overflow); scrollbar-gutter:stable сохраняет ширину.

Deep links #service-* и #detail-* открывают нужную модалку/работу. Запись закрывает окно и переносит к форме с выбранной услугой. No-JS: оригинальные details доступны в потоке, поскольку dialog требует JS. При JavaScript это поведение полностью заменено модальным.
